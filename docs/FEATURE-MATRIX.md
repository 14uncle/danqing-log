## 0. 怎么读

| 档 | 含义 | 用法 |
|---|---|---|
| **对齐** | 我们有，竞品也普遍有 | **不是卖点**。缺一条才输（「缺一条就输给 klogg / LogViewPlus，收费即自杀」），写文案时它只配当资格线，不配当卖点 |
| **缺口** | 竞品有，我们没有 | 已知欠账 / 挂起项 / 从不打算做（后者要写明白，免得每年重问一遍） |
| **创新** | 竞品没有，或只有基础版 | 才是文案弹药。每条必须能落到「对手具体缺什么」或「我们具体的实测数字」 |

**两条纪律**（都是仓库里付过代价的）：
1. **对齐项不许包装成创新**。合并（merge）在 `ROADMAP` 里已明确写成「没有 merge 卖不动，
   **只有 merge 也卖不动**」——它是入场券不是钩子，免费等价物最多（lnav / OtrosLogViewer /
   微软 logmerge / VS Code 插件）。
2. **对竞品行为的任何具体断言，必须有实测记录 + 日期**。「klogg 把 GBK 认成 ISO-8859-1」
   就是一句编造句，且被 2026-09-21 实测证伪（klogg 打开 `demo-cn-gbk.log` 中文正常）。
   下表里凡标 **【待核】** 的竞品格，写进对外文案前必须先补一手实测。

**速度口径（不重复但必须记住）**：碾压**只对 LogViewPlus 成立**（1 GB 冷启动实测 60 s
vs 我们 0.6 s = 100×，其慢有结构原因 = 全量解析入表格）。**对 klogg 禁止任何速度声称**
（同为 mmap，速度平手）。出处：`ROADMAP-v1x.md` §六。

## 3. 创新 / 差异化

### 3.1 结构性（架构决定，抄不走）

| 项 | 我们 | 对手 | 出处 |
|---|---|---|---|
| 大文件冷启动 | 1 GB **0.6 s** | LogViewPlus **60 s**（实测）= **100×**；VS Code 明文 ~10 s；daucloud ~7 s | `PERFORMANCE_REPORT.md` §竞品对比 |
| 更大文件 | 5 GB 冷 ~3 s / 10 GB 冷 6~7 s（实测） | 竞品侧未实测 | 同上（**旧目标「10 GB <3 s」未达成，禁止当成绩引用**） |
| JSONL 字段过滤 | 1 GB **40 ms** | N/A（klogg 无 JSONL）/ LogViewPlus 未实测 | 同上 |
| 零 parse 字段提取 | `memmem` 单遍状态机，不建 `Value` 树 | LogViewPlus 全量解析入表格 | `ROADMAP-v1x.md` §二 腿二 |

### 3.2 品类空白（`DEEP_COMPETITIVE_RESEARCH.md` §五）

| 项 | 缺口实况 | 对外口径要求 |
|---|---|---|
| **JSONL 列化表格视图** | DEEP §2.1 该行**六竞品全 ❌**；LogViewPlus 仅「⚠️ 基础」、VS Code 扩展 daucloud 有 | 必须带限定词「**原生桌面、秒开的**」—— 写「独家/唯一」违规（禁声称清单） |
| 顶层字段迷你语法过滤 `level=ERROR status=50*` | 桌面端空白 | 可直说 |
| **免语法字段查询 UI** | 字段/算符点选 + 只打值 + 自动 AND 追加；Daucloud 的「field pointer + condition + value」三段式是启发源，但**无原生桌面版** | 可直说 |
| 嵌套展开（`user.id` / `tags[0]`） | DEEP §2.1 该行走我们的 ✅ / 三家 ❌ | 可直说 |
| **中文 GBK 自动识别不乱码** | 2026-09-21 实测同文件：LogViewPlus 乱码 / klogg 正常 / 我们正常**且中文可搜** | **只能对 LogViewPlus 说**；对 klogg **不成立** |
| 全本地 / 零遥测 | 商店版 **零网络请求**；便携版仅启动一次 GitHub releases 查询 | 口径在 `docs/privacy-policy.md` |

### 3.3 v1.x 腿一（合并时间线）的组合创新

**单点都不独家，组合是** —— 差异化必须带「**合并 × 大文件性能 × JSONL 列化 × GUI 零语法**」
四件套一起讲（lnav 四腿全覆盖但全挂 SQL/TUI 门槛；LogViewPlus 靠 SQL 且慢）。

| 创新点 | 对手实况 | 我们 |
|---|---|---|
| **每源时钟偏移 + 时区校准** | LogViewPlus 论坛 2021 求 time offset calculator、2024 求无时间戳行的 offset 推算，**至今未满足**；微软 logmerge 硬假设 UTC | ✅ 偏移 ±10 年 / 时区 ±23 h，钳位单真源 |
| **合流态 live-tail（增量合流）** | 竞品合并视图**都是静态**的 | ✅ 增量合流 **27–50 ms / 4 MiB（2.6 万行）**；滞后源（插入位深 198 万行）38–53 ms；追踪态 46–55 ms |
| **跨源 `req_id` 追踪** | lnav / LogViewPlus 靠 SQL | ✅ 跨源扫描 16.99M 行 164–168 ms，命中集重推 66–86 ms |
| **按源着色 / 按源隐藏** | LogViewPlus 论坛 2023-12 求「merged view 里隐藏某文件的消息」**未满足**；微软 logmerge 有按源着色 | ✅ 两者都有（隐藏走掩码重建，159–256 ms） |
| **GUI 零语法** | lnav 全功能但要 SQL + TUI；LogViewPlus 要 SQL | ✅ 点选 + 迷你语法 |
| 合并工作区的命名会话（跨源留存） | LogViewPlus Templates 是单文件 | ✅ |

实测出处：`PERFORMANCE_REPORT.md` §合并（3 源 / 3.00 GiB / 16,985,344 行，就绪 947–967 ms）。
**引用时的口径陷阱**：这是「我们合并 3 源」对「它单开 1 源」，口径不同，
**只有当「大文件 + 多源」一起讲时才成立**（`PERFORMANCE_REPORT.md:106` 同注）。

### 3.4 腿二 / 三 / 四（已建成）

- **字段分析**（腿二，付费）：数值分布 + p50/p99（reservoir 抽样**标注「采样估计」**）+ 枚举 Top20，
  **作用域跟随过滤行集**。1 GiB 全文件单列 1001 ms / 跟随过滤 124 ms。
- **导出三格式**（腿三，付费）：原始行 / pretty JSON / CSV（BOM + CRLF + RFC4180，Excel 不乱码）。
  1 GiB 全集 raw **608 ms** / pretty 18.1 s / CSV 20.7 s。
- **命名工作台会话**（腿四，付费）：过滤器组合 + 搜索历史 + 列配置 + 展开态跨重启。
- **三连**（列配置 / 书签持久化 / 免语法字段查询，2026-09-27 改判付费）：
  `ROADMAP-v1x.md` §一 已当面结清 —— 它们**从未到用户手里**（不存在「扣走我本来该有的东西」），
  收的是「跨重启持久化与点选查询」，**会话内书签与 .log 直用场景保持免费**。

## 5. 维护规则（改能力时同步哪几处）

1. **任何能力增减 / 分层变动** → 改**本文件**对应档位 + 若涉及对外数字则改 `PERFORMANCE_REPORT.md`。
2. **`PERFORMANCE_REPORT.md` §功能对比 表已被本文件取代口径** —— 保留它是因为 README 指向它；
   两表同行列（与 DEEP §2.1 同构），**改一处必须改另一处**。
3. **写任何对外文案前** → 先扫 `docs/ms-store-copy.md`「禁止声称清单」（17 条），再回本文件核对档位。
4. **`COMPETITIVE_ANALYSIS.md` / `COMPETITIVE_GUIDE.md` 是 POC 期存档**（两份文件头已标），
   **禁止引用**：里面「我们 ANSI ✅」「JSONL 独家」等已被证伪（`ROADMAP-v1x.md` §六 二轮清扫）。
5. 标 **【待核】** 的竞品格 → 写进对外文案前必须先补一手实测 + 日期（纪律 2）。
