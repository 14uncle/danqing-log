# 丹青日志 LogLens 隐私政策

- **生效日期**：2026-09-13
- **适用版本**：1.0 及以后
- **适用渠道**：Microsoft Store 版（MSIX）与 GitHub 便携版

---

## 一句话

**丹青日志不收集你的任何信息。** 没有账号、没有统计、没有崩溃上报；你打开的文件、你的配置、它的运行日志，全部只留在你自己的机器上。

下面把这句话拆开讲 —— 包括那**一个**联网动作，它只存在于便携版。

## 一、不收集什么

应用没有账号系统，也没有任何形式的遥测。具体地说，它**不做**下列任何一件事：

- 不收集个人身份信息（姓名、邮箱、账号、设备标识、硬件信息）
- 不采集使用行为（没有埋点，没有匿名统计，没有崩溃上报）
- 不上传你打开的任何文件，也不上传其中的片段
- 不接入广告或第三方分析 SDK
- 不在后台与任何服务器保持连接

清单里只声明 `runFullTrust` 一项能力（桌面应用运行所需）。位置、相机、麦克风、联系人、文件库等能力一概没有声明。

## 二、唯一的联网动作 —— 仅便携版

| 渠道 | 联网行为 |
|------|----------|
| **Microsoft Store 版** | **零网络请求。** 应用自身从不发起连接 |
| **GitHub 便携版** | 启动时一次 HTTPS 请求，查是否有新版本 |

商店版之所以一次都不发：MSIX 应用由商店平台负责推送更新，自己再查一遍是多余的，而且提示「有新版本」时把用户引向 GitHub 还可能让人装成便携版，同一台机器上出现两份安装。**因此商店版把更新检查整条关掉了。**

便携版那一次请求的全部内容：

- **地址**：`https://api.github.com/repos/14uncle/danqing-log/releases/latest`
- **内容**：一个固定的 `User-Agent: danqing-log`。没有查询参数，没有请求体，**不携带任何与你有关的信息** —— 它问的是「这个仓库最新版本号是多少」，与「你是谁」无关。
- **结果**：缓存在本机（见第四节），供下次启动直接读取。
- **失败**：静默忽略，不影响任何功能。

> 这次请求 GitHub 会看到你的 IP 地址。这是任何网络通信的固有属性 —— 与你在浏览器里打开一个网页没有区别 —— 不是本应用额外收集的东西。

## 三、你主动触发的跳转

设置页里有一个「问题反馈」链接。点它，应用会用你的**默认浏览器**打开 GitHub Issues 页面。跳转之后发生什么由 GitHub 的隐私政策管，不经过本应用。

（便携版检测到新版本时，提示里的「前往下载」同理 —— 商店版不会有这个提示。）

## 四、它在你的机器上写了什么

只有三处，都在你自己的用户目录里，随时可以删除：

| 内容 | 位置 | 用途 |
|------|------|------|
| `config.toml` | `%APPDATA%\danqing-log\` | 记住主题、级别侧栏开关 |
| 运行日志 | 程序目录旁的 `logs\`；不可写时退到 `%LOCALAPPDATA%\danqing-log\logs\`，再不可写才用当前工作目录下的 `logs\` | 出问题时排查用 |
| 更新检查缓存 | `%APPDATA%\danqing\update-check-14uncle-danqing-log.json`（**仅便携版**） | 免去每次启动都联网 |

（更新缓存放在 `danqing\` 而不是 `danqing-log\` —— 那是底层框架给整条产品线用的公共配置目录。两条路径都只是本地文件，用途如上。）

商店版的这些路径会被系统重定向到应用自己的私有目录（`…\Packages\14uncle.LogLens_…\LocalCache\`），其他应用访问不到。

**日志里可能包含你打开过的文件路径** —— 它记录的是运行过程，不会发送到任何地方。不想要，直接删掉即可。

## 五、你打开的文件

应用对你打开的文件是**只读**的（内存映射，只映射不写回）。它不会修改、移动或删除你的任何文件。

日志文件可以被外部程序追加（这正是「实时跟踪」要处理的情况），应用本身始终不写。

## 六、关于儿童

应用不为儿童专门设计，也不收集任何年龄信息 —— 因为它谁的信息都不收集。

## 七、政策变更

如有变更，会更新本文件顶部的生效日期并提交到仓库；影响用户权利的变更会在发布说明里注明。

## 八、联系方式

有任何疑问，请提 issue：<https://github.com/14uncle/danqing-log/issues>

## 附录：提交到 Microsoft Store 时怎么填

下表来自同产品线 **danqing-pomodoro 的商店上架实录**（2026-09，已上架）——它是第一手的，
不是推断。**两条都跟直觉相反，照直觉填会白折腾。**

| 字段 | 实测怎么填 | 说明 |
|------|-----------|------|
| 是否访问 / 收集 / 传输个人信息 | **「是」（被强制）** | `runFullTrust` 全信任桌面应用一律被强制成「是」。**选「否」保存后回来会自己弹回「是」** |
| 隐私策略 | **「提供隐私策略文本」直接粘贴** | 比「提供 URL」干净：免托管 |

**别在「是/否」上较劲** —— 表单不接受「否」，硬扛只会反复弹回。
「是否收集」那个勾代表的是**平台对全信任应用的分类**，不是本应用的实情；
**说清实情的地方是隐私策略文本本身** —— 正文第一节已经写明「不收集任何信息」，
那才是给用户和审核员看的。

**关于用 URL**：本仓库当前是**私有**的，所以本文件的 GitHub 链接**对外打不开**，
现在填了就是给审核员一个 404。要用 URL 得先把仓库转为公开。
（本产品计划开源，届时 URL 可行 —— 但 pomodoro 上架时仓库**已经是公开的**，
它仍然选了贴文本，理由是省去托管。这里照办。）

因此提交步骤是：

1. 选「提供隐私策略文本」，粘贴**本文件正文**（`## 附录` 之前的全部内容，去掉
   Markdown 标记：`#` 标题符号、`**` 加粗、表格竖线换成普通文本即可）
2. 顶部三项元信息（生效日期 / 适用版本 / 适用渠道）**要一起粘进去**
3. 粘贴后**在商店后台预览一遍**，确认没有 Markdown 残留符号
4. **此时商店里就有了第二份副本** —— 以后改本文件，必须同步改商店后台那份。
   提交时把「贴的是哪一版」记进 `CLAUDE.md`，将来好对
