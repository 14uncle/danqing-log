# SPEC-live-tail: tail 跟随 + 实时过滤

> 模块 id: `live-tail` (地图与共享约定见 `../../SPEC.md`)。依赖 `core-viewer`
> 的截断/轮转生存原语与增量索引 API; 与 jsonl-table 可并行构建。

## Objective

`tail -f` 的桌面 GUI 形态: 日志写进来, 视图跟上去——生产排障的标准姿势
(klogg/LogViewPlus 用户心智)。tail 是意图文档钦定的日频刚需 (MVP③),
也是技术风险② (截断/轮转) 的正面战场。

## 范围

**In**:
1. **增长检测**: 250ms 轮询文件 stat (len/mtime)。danqing OnDemand 可见态本就有
   ~60fps tick, 轮询零额外唤醒成本; 不引入 ReadDirectoryChangesW (复杂度不值)
2. **增量索引**: 只对新字节区间跑 memchr 行索引追加 (不重扫全文); 处理
   「上次末尾不是完整行」的续行拼接
3. **跟随模式**: `F` 键 toggle (底栏显 FOLLOW 标记); 新行到达自动滚到底;
   用户向上滚动即脱离跟随 (不打扰阅读), 跳回底部 (End) 自动恢复跟随
4. **截断/轮转生存**: len 缩小或 inode 级变化 (Windows 用 len+mtime+首块哈希启发)
   → 全量重建索引 + 状态栏明确提示「文件已截断/轮转」; 全程不崩不丢书签语义
   (书签按行号, 重建后越界书签丢弃)
5. **实时过滤**: 过滤激活时, 增量行只跑过滤判定追加命中表 (不全量重跑);
   搜索命中表同理增量追加; 底栏命中计数实时更新

**Out**: 多文件同时 tail / 时间戳合并 (v1.x 付费层); 远程 tail (SSH, 永久 Out);
文件压缩包内 tail (gzip, 永久 Out)。

## 设计要点

- **原子切换**: 截断/轮转的重建在新 LogFile 完整建好后一次性换入视口
  (读旧建新, 切换 O(1)); 渲染永远只见一致快照, 这是 core-viewer 残余竞态
  窗口的实际收窄机制
- **增量过滤的语义一致性**: 追加路径与全量路径必须产出同一命中集
  (单测: 先全量过滤再追加 N 行 vs 直接全量过滤含 N 行, 两表相等)
- **空闲税**: 无增长时 250ms 轮询 = 一次 stat 系统调用, CPU 占用可忽略;
  隐藏态 (OnDemand Wait) 不轮询 (窗口不可见时文件照长, 重新可见时一次性追平)

## Success Criteria

- [ ] 人工验收: `genlog` 持续追加的 1GB 文件, 跟随模式下新行 ≤1s 内出现,
  滚动流畅无抖动; 向上滚脱离跟随, End 恢复
- [ ] 人工验收: 过滤激活 (`level=ERROR`) 时新命中行 ≤1s 内出现, 底栏计数正确
- [ ] 人工验收: tail 进行中外部截断文件 → 状态栏提示 + 视图正确重建, 进程不崩
- [ ] 单测: 增量索引追加与全量重建结果一致; 续行拼接正确; 增量过滤与全量过滤
  命中集相等; 截断后越界访问不崩
- [ ] 空闲税实测: 无增长时进程 CPU < 1% (任务管理器读数, 人工验收)
- [ ] 三件套绿
