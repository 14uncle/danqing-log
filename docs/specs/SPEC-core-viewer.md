# SPEC-core-viewer: 引擎硬化 + 完整查看器交互

> 模块 id: `core-viewer` (地图与共享约定见 `../../SPEC.md`)。构建序第一棒,
> live-tail 与 jsonl-table 都建立在本模块的引擎原语上。

## Objective

把 POC 引擎硬化成正式版内核, 并补齐查看器交互: POC 证明了「快」, 本模块证明
「稳 + 好用」——文件被截断/轮转而崩是 POC 已知边界, 正式版必须生存; UTF-16/GBK
打不开是 POC 已知边界, 正式版必须正确显示。用户 = 日频查日志的开发者/运维/支持
(造物主本人在场质检)。

## 范围

**In**:
1. **编码检测与显示** (技术风险③): BOM 优先 (UTF-8/UTF-16LE/BE), 无 BOM 走采样
   启发式 (UTF-8 合法性 → GBK 双字节统计); UTF-8/UTF-16/GBK 三种正确显示
2. **截断/轮转生存原语** (技术风险②的引擎一半): 行访问越界返回 None 不崩;
   文件 stat 快照 (len + mtime) 与索引重建 API, 供 live-tail 轮询驱动
3. **行索引内存优化**: POC 行偏移 Vec\<u64\> 635 万行 ≈ 48 MB → 分段 u32 或
   压缩表示, 目标 ≤ 16 MB/GB
4. **虚拟视口补完**: PageUp/PageDown (引擎缺口, 打磨寄生修进 danqing NamedKey,
   联动提交); 水平滚动 (Shift+滚轮 + 底部细滚动条); 行锚定 f64 不动
5. **正则搜索 UI** (MVP④): `/` 或 Ctrl+F 开搜索栏 (顶栏, 复用 danqing TextInput),
   后台线程全文件搜索 (复用过滤架构 worker + rev + tick), Enter/Shift+Enter
   跳下/上命中, 可见区命中行内高亮, 底栏命中计数
6. **级别着色**: 保留 POC 实现 (行首 200 字节关键字)
7. **书签** (MVP⑦): `b` 切换当前行书签, `'` 循环跳下一书签, 书签行槽位标记;
   会话内有效, 不持久化 (持久化归 v1.x 会话功能)

**Out**: tail 跟随 (live-tail); JSONL 列化/嵌套 (jsonl-table); 编辑/导出/多文件;
最近文件列表; 窗口位置记忆 (danqing 有现成 Remember 机制但不在 MVP In 清单, 不发明需求)。

## 设计要点

- **编码策略**: UTF-16 = 2 字节编码不适合字节级 \n 索引 → 打开时一次性转码 UTF-8
  内存副本 (1GB UTF-16 ≈ 500MB UTF-8, 可接受), 之后全走 UTF-8 路径; UTF-8/GBK =
  原字节索引 + 行级惰性解码 (GBK trail byte 范围 0x40–0xFE 不含 0x0A, 字节索引安全);
  搜索查询按文件编码转成字节再搜 (GBK 中文查询可行), 内存零膨胀
- **截断残余风险 (诚实记录)**: Windows 上 mmap 后文件被截断, 即使访问原长度内偏移
  也可能崩 (页面失效)。clamp 防不住, 只能靠 live-tail 的快速轮询 + 原子切换 LogFile
  缩短窗口; 残余竞态接受并文档化 (对手同有此问题), 不因追求完美安全引入拷贝开销
- **搜索高亮**: 命中区间字节偏移 → 行内高亮 rect; 高亮只画可见行, 与视口同生命周期
- **索引压缩**: 分段 (64K 行/段, 段内 u32 相对偏移) 优先于变长编码 —— 随机访问
  保持 O(1), 实现最笨先对

## Success Criteria

- [ ] 全局性能基线全部达标 (见 `../../SPEC.md` 表, logbench 复跑数字为证)
- [ ] UTF-16LE/BE (带 BOM) 与 GBK 测试 fixture 打开显示正确, 行数与原文一致
- [ ] 打开状态下文件被外部截断/改写: 不崩, 越界行访问返回 None (单测模拟)
- [ ] 1GB 文件行索引内存 ≤ 16 MB (logbench 输出实测)
- [ ] 搜索 UI 人工验收: `/ERROR` 回车逐命中跳转 + 可见区高亮 + 底栏计数正确
- [ ] 书签人工验收: `b`/`'` 行为如上, 行号槽有标记
- [ ] PageUp/PageDown 生效 (danqing 联动提交, commit message 注明关联)
- [ ] 三件套绿; 新增测试覆盖: 编码检测、截断越界、压缩索引随机访问一致性
