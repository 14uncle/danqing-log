# SPEC-jsonl-table: JSONL 列化 + 嵌套展开 + 过滤增强

> 模块 id: `jsonl-table` (地图与共享约定见 `../../SPEC.md`)。依赖 `core-viewer`
> 的引擎原语; 与 live-tail 可并行构建。POC 前提② demo (`src/jsonl.rs` +
> 表格模式) 是本模块的种子, 已证路线: 零 parse memmem 提取 235ms/1GB。

## Objective

把前提② demo 升级成正式版主炮——本产品对 klogg 的本质差异点
(「klogg 的速度 × LogViewPlus 的结构化」的结构化那一半), 对标并超过
daucloud.json-viewer (VS Code 扩展, GB 级虚拟化表格 + JSON Pointer 过滤)。

## 范围

**In**:
1. **真 parser 换 memmem (显示路径)**: 单元格渲染改为逐行 serde_json parse
   —— 只 parse 可见行 (恒定成本), 嵌套值安全显示; memmem 提取退役出显示路径
   (消除 POC「`,"key":"` 内嵌误判」已知边界)
2. **行内子行嵌套展开** (2026-09-05 用户裁决): 点展开按钮/行首 ▶ 展开,
   每个嵌套节点 = 一条缩进子行 (行高恒定, 行锚定数学不破); 数组与对象同法;
   展开态按文件行记忆, 折叠恢复
3. **点路径字段过滤**: `user.id=42` 寻址嵌套字段; 过滤保持
   memmem 粗筛 (最内层 key) + serde_json 精确验证 (路径导航) 两段架构
   —— 1GB 全文件 parse 必慢, 粗筛把候选压到千行级再验证
4. **数值比较算子**: `status>=500` `duration_ms>1000` (`>` `<` `>=` `<=`),
   日志场景高频; 与等值/前缀通配共存于 AND 分词语法
5. **列化渲染升级**: 列宽采样自适应保留; 嵌套值在单元格内紧凑显示
   (`{"a":1}` 截断省略); 溢出右缘的列整列不画保留 (POC 行为)

**Out**: 列宽拖拽/列显隐/列重排 (v1.x); 根为数组的 JSON (非 JSONL) 文件;
JSON 美化导出 (v1.x 付费层「导出」); 模式推断外的类型系统 (时间戳列特殊格式等, v1.x)。

## 设计要点

- **展开的行模型**: 显示行 = 文件行 ∪ 展开子行。`BTreeMap<文件行号, 子行数>`
  存展开态, 显示行↔(文件行, 子行偏移) 双向映射走前缀和 O(log n);
  展开内容惰性 parse (只 parse 展开的那一行), 拍平成 (路径, 值, 深度) 子行序列;
  展开 1 万节点视口成本恒定 (行锚定虚拟化不变)
- **过滤两段架构的性能契约**: 粗筛 (memmem 最内层 key) 候选率必须够低,
  否则退化成全量 parse; `level=ERROR` 这类扁平查询应识别为「无需验证」直通
  (POC 路径, 235ms 不退化); 验证路径只在含点路径或比较算子时启用
- **检测/列发现保留 POC 采样策略** (64 行检测 / 512 行列发现 / ≤16 列),
  唯一改动是 serde_json 已有 `preserve_order`, 列序 = 首见序
- **与 live-tail 的接缝**: tail 增量行进表格模式时, 过滤增量追加同 live-tail
  模块契约; 展开态在新行到达时不受影响 (展开按文件行号锚定)

## Success Criteria

- [ ] 性能: `level=ERROR` 扁平过滤 1GB ≤ 400ms (POC 235ms 基线 + 验证架构税上限);
  `user.id=42*` 点路径过滤 (嵌套 fixture) 1GB ≤ 2s
- [ ] 单测: 嵌套 fixture (含 `,"key":"` 内嵌字符串的对抗样本) 单元格显示正确,
  memmem 时代的误判样本全部不再误判
- [ ] 单测: 展开行模型 —— 展开/折叠/滚动越界/过滤叠加展开的行号映射一致;
  比较算子边界 (=, >, <, 负数, 浮点) 正确
- [ ] 人工验收: 1GB JSONL 打开 → 表格 → 展开某行嵌套对象 → 滚动流畅;
  `status>=500` 过滤结果与 logbench 交叉验证一致
- [ ] 三件套绿
