## 一句话

用户在终版真机上 5 分钟撞出 6 个选区/复制症状。把这盘面补成**全产品一致的手势体系** ——
矩阵里每个格子要么工作、要么有意识地留空。**进 v1.0, 阻塞发布**。

## 结论 (用户逐行确认)

- **Outcome**: 选区/复制一致性 —— 三种内容形态 (原始 .log / 表格 .jsonl / 展开块)
  各有完整、可预期的复制手势; **进 v1.0, 阻塞发布**。
- **User**: v1.0 首发用户 —— 复制是日志查看器上手 5 分钟内必用的核心肌肉。
- **Why now**: 用户终版真机自查撞出 6 症状; 截图未拍、商店未提交, 现在按住**零浪费**;
  「等发布决策」本就挂着, 无已承诺发布日可失约。
- **Success** (改完后的行为矩阵):
  - **双击分词** (框架 `token_at` 重写, (c) 混合连接器规则): 词字符 + 连接器
    (`- : . / = @ _` 等, 两侧均为词字符时并入) → 时间戳 / IP / `level=ERROR` / 路径**整选**;
    逗号、分号、空格、引号断开 (`hello,world` 分得开); **中文逐字**。
  - **.log 原始模式**: 双击选词 (新分词) / 框选 / 文本选区 Ctrl+C —— 已有保留;
    **选中行 Ctrl+C = 复制整行** (翻案旧 spec「只认文本选区」决策)。
  - **.jsonl 表格模式**: 选中行 Ctrl+C 复制原文 —— 已有保留;
    **双击单元格 = 选中该单元格完整值, Ctrl+C 拿全值** (不受截断省略影响); 不做框选。
  - **展开块**: **双击选词 / 框选 / Ctrl+C 复制子行那条 `label = value` 文本**, 全做。
- **Constraint**: ① 中文逐字, **不引分词库** (jieba 级依赖 + MB 词典, 对日志查看器不值;
  单字 + 框选兜底); ② 表格模式不做词级框选 (格子窄且截断, 价值低工程量最大);
  ③ 框架改动走既有联动顺序 (danqing 先 push → 本仓 `cargo update` 重钉)。
- **Out of scope**: 右键菜单 (框架无窗口内上下文菜单组件, 另一个量级的活) /
  Ctrl+A 全选 (与 50 万行复制上限纠缠, 单独设计) / 三击选整行 / 中文词组分词。

> 三条锁定假设 (agent 提议、用户未反对): 原始模式行复制翻案 / 展开块全做 /
> 右键·Ctrl+A·三击本轮不做。

## 实现路径预判 (spec 阶段核实)

- `token_at` 重写动的是**框架** (`danqing::text::selection`) → 联动顺序:
  danqing 先 push → 本仓 `cargo update -p danqing` 重钉 lock → 两仓分别提交注明关联。
  pomodoro 不用 `token_at` (纯产品侧函数), 波及面预期为零, spec 阶段核实。
- 展开块命中几何复用原始模式 `row_geom` 那套 (`view.rs:1113`), 子行是整宽纯文本, 无列裁剪。
- 表格单元格双击: 命中只需「x 落在哪一列」, 不建字符几何; 复制走完整值不受截断影响,
  与行复制「复制原文不丢信息」同一哲学。
