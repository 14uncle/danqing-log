## 分层原则（一句话）

**免费层 = 看懂；付费层 = 批量 / 留存 / 交付。**

- 「看懂」= 读一批日志、搜、定位 → 免费。**缺一条就输给 klogg / LogViewPlus，收费即自杀。**
- 「批量 / 留存 / 交付」= 跨文件、跨会话、把结果交给别人 → 付费。
- **反例警戒**：把 v1 的欠账当付费钩子，用户会读成「扣走我本来就该有的东西」——
  这是付费墙最招骂的形态。凡属 v1 欠账者，一律进免费层。

## 一、免费层

### 已交付（截至 2026-09-12，待人工验收）

mmap 秒开 GB 级 / 行锚定虚拟滚动 / 正则搜索+高亮+命中导航 / live tail+实时过滤（增长检测、轮转截断重建）/
JSONL 自动检测+列发现+字段过滤迷你语法+嵌套展开 / 编码检测（UTF-8·UTF-16·GBK·Latin-1）/
级别着色 / 书签（会话内）/ 文本选区复制 / 深浅主题 / 设置卡 / 异步打开 / 巨量追平

实测数字（release，本机 1GB JSONL 483 万行，`logbench`）：mmap 130 µs、索引 96 ms（热）、
`level=ERROR` 235 ms —— 这是发布素材的弹药，也是免费层的价值证明。

### 欠账与缺口（补在免费层，不收费）

| 项 | 性质 | 出处 |
|---|---|---|
| 列宽拖拽 / 列显隐 / 列重排 | v1 欠账 | `SPEC-jsonl-table.md:30` |
| 书签持久化 | v1 欠账（**2026-09-12 由 v1.x 改判至此**） | `SPEC-core-viewer.md:29` |
| **等级直方图**（Info/Error/Warn/Fatal 计数侧栏） | 缺口，2026-09-12 新增 | — |
| 时间戳列类型系统 | 打磨 | `SPEC-jsonl-table.md:31` |
| 免语法字段查询 UI（列发现采样结果做成下拉点选） | 缺口，**提议待裁** | — |

**等级直方图为什么必须免费**：它是 LogViewPlus 最能卖钱的一个功能（截图：Info 4,544,133 /
Error 43,464 / **Fatal 4,760**，一眼知道该看哪行），也是排障的第一动作。免费层缺它，
「不比 LogViewPlus 差」这句话当场就说不出口。实现便宜 —— 索引时顺带统计即可。

**免语法字段查询 UI**：Daucloud 的 `field pointer + condition + value` 三段式，外加「12 sampled fields」
把字段名摆出来给用户点。你的 `level=ERROR status=50*` 要求用户**先知道字段名、先学会语法** ——
这是**可发现性缺口，不是功能缺口**，而列发现本来就做了 512 行采样，把结果做成下拉即可。

**书签持久化的改判说明**：原记 v1.x。改判理由 —— 它是 v1 欠账不是新价值，锁进付费层会招骂。
但**工作台会话**（下节）是另一回事。

## 二、付费层（v1.x）

### 腿一：多文件时间戳合并 ★★★

- **做什么**：多个日志文件按时间戳归并成一条时间线；跨文件 `req_id` 跳转
  （一个请求在 auth → worker → db 之间追下去）。
- **为什么值钱**：四缺里唯一 LogViewPlus 有而你无的功能，也是「LogViewPlus 替代品」定位的入场券。
  LogViewPlus 靠 SQL 做跨文件查询，笨重且慢 —— 真空。
- **成本**：**高**。引擎 + UI 双改，正是 intent「三大技术风险」之一的多文件合并。
- **出处**：`SPEC-live-tail.md:27`

### 腿二：字段分析 ★★★

- **做什么**：对已提取字段做聚合 —— 数值列分布/分位数（`duration_ms` 的 p50/p99/最大）、
  枚举列取值分布（`status` 的分布）。
- **为什么值钱**：**手上唯一没被变现的资产。** 483 万行 235 ms 的字段提取能力（`memmem`，零 parse）
  已经证明，但目前只用来「找那一行」。运维问「昨天 p99 多少」，现在得写脚本或导进别处才能答。
  竞品要么慢（LogViewPlus 结构化 1GB 卡死）、要么没结构（klogg）。
- **成本**：**中低**。提取路径现成；分布是线性扫描，分位数需排序或近似算法（t-digest 之类）——
  仍**比腿一便宜一个量级**。
- **风险**：字符串值切取换真 parser 的边界问题（`SPEC-jsonl-table.md:16` 已记为待办），
  聚合是对提取结果的二次消费，边界错误会被放大 —— 腿二开工前需先解决这个。

### 腿三 / 腿四：交付与留存 ★★

| 项 | 内容 | 出处 |
|---|---|---|
| 导出 | 过滤结果导出、JSON 美化导出、CSV | `SPEC-jsonl-table.md:31` |
| 工作台会话持久化 | 命名会话（过滤器组合 + 搜索历史 + 列配置 + 展开态）跨会话保存/切换 | `SPEC-core-viewer.md:29`、intent:52 |

单独看都不构成购买理由，但它们是腿一/腿二的收尾：用户分析完，总得能把结果交出去、
把自己搭起来的工作台留下来。

> **与会话持久化的切分**：书签持久化 → 免费层（欠账）；**命名工作台会话** → 付费层（真增值，
> 对标 LogViewPlus Templates）。两者名字相近，别混。

### 基础设施（非卖点，但前置）

- MS Store 授权 / trial 轨、Store 更新轨：`SPEC-settings.md:68`
- 试用过期 → **降级到免费层，不是变砖**（这是整套试用方案能成立的前提）

## 三、渠道与收费

| 渠道 | 免费层 | 付费层 |
|---|---|---|
| **GitHub（主）** | 永久免费开源 | **$29** 买断（2026-09-12 定档） |
| **MS Store（辅）** | 同 GitHub | Store 内置 trial → 买断；**过期降级到免费层** |

- **不设订阅**（Dadroit 按大小收订阅正是其口碑裂缝，反向操作即差异化；产品线一致）。
- 企业档 **$59/seat**（2026-09-12 定档）—— 按 LogViewPlus 个人↔企业的 2.1 倍差折算；
  原 $89 在个人档降到 $29 后成 3 倍差，过陡。
- **为什么不是「v1.0 全功能 + 试用期」单轨**：见 intent §定价锚与渠道三条裁因
  （发布推迟 / 丢 GitHub 开源叙事 / 试用期撞生产事故）。
- **前提③（首单外检）不必等 v1.x** —— MS Store 试转付费的首单即可判定。
