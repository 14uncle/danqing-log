## 详细说明

### ⚡ GB 级文件，打开就是秒开

1 GiB 实测（release 构建，本机无窗口基准，完整报告见仓库 `PERFORMANCE_REPORT.md`）：

| 指标 | 明文日志 | JSONL |
|---|---|---|
| 建立索引 | 92 ms | 94 ms |
| 全文正则搜索（默认大小写不敏感） | 115 ms | 129 ms |
| 字段过滤 | — | 40 ms |
| 随机访问 | 0.52 µs/行 | 0.58 µs/行 |

打开 1 GB 文件约 0.6 秒（冷）/ 0.09 秒（热）。索引全程异步：**文件还没索引完，
窗口就能滚动、就能搜**，底栏实时显示 `{pct}% · {done}/{total} MiB`，
中途可以取消，也可以直接换开另一个文件。

> **数字出处与一处易踩的坑**（2026-09-13 核，**2026-09-15 复测刷新**）：
> 上表取自 `PERFORMANCE_REPORT.md`（2026-09-15 复测，热缓存，Release 模式，
> Windows 11，1 GB 文件）。搜索一栏自 2026-09-15 起为**默认大小写不敏感**的值
> （比敏感匹配慢约 1.6 倍，后台扫描，体感无差）—— 对外文案别把旧的 71/69 ms
> 当作当前值。
> `../danqing/docs/intent/log-viewer-poc.md` 里另有一组更旧的 POC 数字（索引 **425 ms**、
> 字段过滤 **235 ms**）—— 那是 2026-09-05 POC v0 的值，**现在被 `PERFORMANCE_REPORT.md`
> 当成「目标值」列着**（要超越的基线），不是当前实测。**别看到「235 ms」就以为是过滤耗时
> 去改文案**，两处对不上是同一个数的两种身份。

### 🔍 找得到，才叫查看器

- **正则搜索**：全文扫描（`regex::bytes`），可见区高亮，`Enter` 逐条跳命中；
  **默认大小写不敏感**（`error` 命中 `ERROR`），要精确匹配写 `(?-i)`
- **级别直方图**：左侧栏把 FATAL / ERROR / WARN / INFO / DEBUG 分六桶计数，
  **点柱条即筛出该级别**，`清除筛选` 一键退回
  （对数刻度 —— 线性刻度下 454 万条 Info 会把 4760 条 Fatal 压成亚像素，
  而后者才是你要抓的那根）
- **实时跟随**：日志还在写，新行 1 秒内出现；上滚自动脱离跟随，`End` 恢复；
  外部轮转 / 截断自动重建
- **书签**：看到一个可疑行先记下，回头再查

### 📋 JSONL 不只是文本

JSONL 打开即自动检出并列化成表格：

- **自动列发现**，16 列上限，嵌套对象以子行展开（`→` / `←` 键）
- **字段过滤**迷你语法：`level=ERROR status=50*`（空格分词 AND、尾缀 `*` 前缀通配、
  裸词整行子串）—— 字段名与值**均默认大小写不敏感**（`LEVEL=error` 等价），
  跑在工作线程，**不冻界面**
- 表格 / 原始模式 `Ctrl+T` 随时互切

### 🇨🇳 中文日志不会变乱码

- UTF-8（含 BOM）、UTF-16 LE/BE（有无 BOM 均可）、**GBK（行级 CP936 解码，中文可搜）**、
  其余单字节编码按 Latin-1 兜底
- 编码自动检测，不用你选

### 🪶 轻、纯本地

- 安装约 11 MB，纯 Rust 编写，无运行时依赖
- **应用自身不发任何 HTTP 请求** —— 没有账号、没有遥测、没有崩溃上报、没有广告
  （对外通信只经系统 Microsoft Store 服务：更新检查与后续授权查询，2026-09-22 起如实披露）
- 你打开的文件**只读**打开（内存映射），不会修改或删除
- 配置与日志只写在你自己的用户目录，随时可删

### 🆓 免费，没有但是

**v1.0 全部功能免费**，无内购、无广告、无需注册、无功能墙。

> ⚠️「无内购」是 **v1.0 的事实**，不是产品线的永久承诺 —— 见文末
> 「v1.x 上架时必须改什么」。写「本版本」而不是留白，就是为了让这句话
> 在 1.x 那天**读起来明显该改**，而不是变成一句没人注意的假话。

### 完整信任说明（`runFullTrust` 的用途）

> 本应用是自绘界面的桌面工具：窗口内容由 GPU 直接绘制（非系统标准控件），
> 需要读写用户通过文件对话框选定的本地日志文件（以只读方式内存映射打开，
> 不会修改原文件），并在系统托盘常驻图标以便快速唤出。
> 应用不访问网络，不收集任何信息。

⚠️ **别照抄 pomodoro 的这句** —— 它的版本里写了「全局快捷键」，
而**本应用不声明任何全局热键**（`main.rs` 里 `hotkeys: vec![]` 显式置空），
写了就是与包内事实不符。

## 踩坑记录（继承自 pomodoro 实测，逐条与我们相关）

1. **支持信息填了邮箱 = 商店页「支持」变成空白页**（pomodoro 2026-09-05 踩）：
   同时填邮箱 + URL 时，商店页优先用 `mailto:` 邮箱；无默认邮件客户端的机器
   （国内大多数）点开是空白页。**只留 URL。** 改属性是纯元数据提交，不必重打新包。
2. **`runFullTrust` 强制「收集个人信息 = 是」**：选「否」保存后回来**会自己弹回「是」**，
   并强制要求隐私策略。别再在「是/否」上较劲，走「提供隐私策略文本」。
3. **基础价格下拉没有「免费」项**：选 `0`。
4. **7 个关键词报「最多 7 个」**：通常有幽灵第 8 个空 chip，全清空重填。
5. **别用「新建应用」建重复预留**：在已有产品下填写；误建草稿要删。
6. **侧载测试同版本号重装不刷新图标缓存**：每次验证图标相关改动必须 bump 版本号。
7. **任务栏图标垫蓝底 = 包缺 `resources.pri`**：本仓 `build_msix.ps1` 已含 MakePri 步骤。
8. ⚠️ **上面第 1、2 两条对我们是「预防」而非「已发生」** —— 我们还没提报过。
   提报完把实际遇到的补进这一节，并同步进 `CLAUDE.md`。

**v1.0 是纯免费层，没有内购。** 1.x 会通过商店 **加载项（add-on）** 上线内购 ——
用户在这里已经把话说明了。届时**下面每一处都要动**，因为 v1.0 的文案里
「无内购 / 不联网 / 零网络请求」**三条同时失效**（其中「不联网/零网络」已在 2026-09-22 的更新检查批次先行修正）。

### 1. 代码：授权查询会引入一次对外通信

pomodoro 已经有 add-on，它的实现是第一手参考（`danqing-pomodoro/src/license.rs`）：

```
StoreContext::GetDefault()  →  GetAppLicenseAsync()  →  AddOnLicenses()
```

即 WinRT 的 `Windows.Services.Store`，**由商店服务broker**。这是**进程外**的调用 ——
本应用自己仍然不发 HTTP，但对隐私政策而言，它**已经不是「零联网」了**。

> ⚠️ pomodoro 代码里留着一条实测坑：`StoreAppLicense::IsActive` 是**应用级**许可证，
> **免费上架时所有安装者都是 `true`**，拿它判断内购永远为真 ——
> **必须遍历 `AddOnLicenses`**。照抄时别把这段简化掉。

### 2. 隐私政策（`docs/privacy-policy.md`）

- **顶部「适用版本」由 `1.0` 改成 `1.x`**，并更新生效日期（现在钉死 1.0 就是为了这一天）
- **第二节要重写**：不能再写「商店版零网络请求」。要新增一段说明
  「查询购买授权时会经由 Microsoft Store 服务；购买与付款由 Microsoft 处理，
  我们不接触也不存储任何支付信息」
- **商店字段是第二副本**（2026-09-22 update-badge 批次追加）：商店版现在**还有更新检查**
  （经 Microsoft Store 服务查待装更新 + 点「更新」拉起系统更新界面，不发 HTTP），
  隐私政策正文已披露；**下次提交时要把新正文重新粘进 Partner Center 的
  「提供隐私策略文本」字段** —— 店里那份是第二副本，不粘就是过期披露
- 正文「不收集什么」那条**依然成立**（我们不收集），但要避免让第二节与它读起来矛盾

### 3. 商店后台

| 项 | v1.0 | v1.x |
|---|---|---|
| 定价 | 免费 | **免费 + 应用内购买** |
