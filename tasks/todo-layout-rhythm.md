## 任务

- [x] **T1: 展开块给底色（略深）** —— 机器部分 ✅ 2026-09-13
  - 说明: 展开的子行原先与真实行**长得一模一样**（只差没有行号）, 用户分不清
    「这坨是第 1 行展开的」还是「又是几行日志」。
  - Acceptance: ① 新增 `expand_block_bg(theme)` —— **产品语义, 放产品侧**,
    与 `bookmark_color` 同一处理, **不扩公开 `Theme` trait**;
    ② 子行先铺该底色再画字; ③ **斑马不盖展开块**（块要靠单一底色读作「一整块」,
    交替条纹会切碎它）; ④ 选中/hover 仍压在块之上（那两态必须保持可见）
  - 实测（两个主题的知觉台阶**几乎相等** —— 模块 2 想要的跨主题一致性, 这里是自然达成的）:

    | | 底 | 块 | Δ`L*` |
    |---|---|---|---|
    | 浅色 | `#F0F8F6` (L\* 96.95) | `#E4EEEA` (L\* 93.27) | **−3.68** |
    | 暗色 | `#191920` (L\* 9.04) | `#111117` (L\* 5.26) | **−3.79** |

  - 回归锁 `expand_block_bg_is_a_slightly_darker_step_in_both_themes` **先红后绿**
    (先报 E0425 函数不存在), 断言两主题都「与底不同」且「**比底深**」——
    用户裁定的是「略深」, 不是略浅。
  - Files: `src/view.rs`
  - Scope: S

- [x] **T2: 斑马与 hover 拆成两个通道** —— 机器部分 ✅ 2026-09-13
  - **触发（用户实机报）**: ① 暗色下 hover 与奇数行背景色相近 —— 悬停**奇数行**
    时颜色**完全不变**, 悬停**偶数行**时 hovered 行与左右斑马行**三行连成一整块**;
    ② 浅色下 hover 太浅看不清。
  - **根因**: 斑马与 hover **共用 `th.surface_variant()`** —— 同一支 token 承担两个
    语义通道, 必然撞车。浅色那支更糟: 它是**不透明色** `#EEF6F2`, 与底色
    `#F0F8F6` 只差 2/255 (Δ`L*` **−0.74**), 等于没有 —— ② 的成因。
  - **修法**: 新增 `row_band_bg()` / `row_hover_bg()`, 两主题各给一对。
    hover 的台阶**刻意比斑马大一档**, 这样悬停奇数行还是偶数行都拉得开。
  - 实测（解方程得到的目标值, 非估算）:

    | | 底 | 斑马 | hover | 斑马 Δ`L*` | hover Δ`L*` | 两者间距 |
    |---|---|---|---|---|---|---|
    | 浅色 | `#F0F8F6` | `#E6EEEC` | `#D6DEDC` | −3.49 | −9.12 | **5.6** |
    | 暗色 | `#191920` | `#26262D` | `#393940` | +6.38 | +15.17 | **8.8** |

  - **暗色斑马观感保持不变**: 新值 `#26262D` 与 `surface_variant()` 原本的渲染结果
    几乎相同 (Δ`L*` +6.38 vs +6.3) —— 模块 2 校准过的那条没被动。
  - **浅色斑马第一次真正显形** (原先 −0.74 等于没有) —— 这是**有意的连带变化**,
    用户此前说「斑马保留」, 而保留一条看不见的斑马没有意义。**须真机复看**。
  - 回归锁 `row_band_and_hover_are_separate_channels` **先红后绿**
    (先报 E0425 两个函数不存在), 断言: 两两不同、且 **hover 的台阶必须大于斑马的**。
  - Files: `src/view.rs`
  - Scope: S
